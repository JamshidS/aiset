# aiset: feature inventory

Status: 2026-10-15. This document collects in one place what the system has today and what it is missing; use it to pick the next piece of work. For detailed usage, see [README.md](../README.md).

Legend: ✅ works · 🟡 partial / limited · ❌ missing

## 1. Team and workflow

| Feature | Status | Summary |
|---|---|---|
| `aiset run <issue>` (preview) | 🟡 | Work an issue with the team, with approval before a draft PR. Accepts positive numbers, `#123`, `owner/name#123` and github.com issue URLs; other preview limitations remain (see the [user guide](USER-GUIDE.md#work-a-github-issue-aiset-run-preview)). |
| Tester | ✅ | Runs tests, lint and type-check in the changed repos, and writes tests when needed. `STATUS: pass/fail`. |
| Integration checker | ✅ | Checks the contract between services (API fields, types, enums, shared tables). Read-only. |
| AWS and Teleport agents | ✅ | Infrastructure questions; changes stay proposals until the user approves them. |
| Task board | ✅ | Shared memory per request: `brief.md` (goal, criteria, decisions), `contract.md` (API shape), `handoff/<agent>.md`, `log.md`. The PM doesn't relay messages between agents. |
| Episodes | ✅ | A short summary the PM writes when a task closes (task, agents, outcome, files touched, decisions, pitfalls). Read in later work. |
| Report format | ✅ | Every agent ends with a `STATUS:` line; the office's task board columns come from it. |
| `MODEL:` line | ✅ | The PM writes the model and the reason for it on every assignment; the office shows it on the assignment card. |
| Knowledge briefs | ✅ | Long-term memory per agent; agents add what they learn under `## Field notes`. Regenerated by asking the PM to "refresh … knowledge". |
| Brief indexes | ✅ | `brief_index.py` writes a table of sections, line ranges and token sizes for each brief; agents read the index first, then only the section they need. The office refreshes stale ones on every poll. |
| Setup on any project | ✅ | `init_team.py <folder>`: scans the repos, detects the stack, and generates an engineer per repo plus a PM, tester and integration checker; writes everything under `<folder>/.claude`. Several teams can live side by side. |
| Monorepo and per-stack teams | ✅ | When the root folder is a single git repo, service folders become units; above 12 units (or with `--group stack`) there is one engineer each for Java, Node, Python and DevOps. DevOps owns the root CI and build files. Team files stay local via `.git/info/exclude` (shared with `--share`). Set up with `tkm-microservices` (52 services). |
| Roster and renaming | ✅ | Names live in `roster.json`; the office copies a change into the agent files within a few seconds (`sync_names.py`). |
| Helper agents (`helpers`) | ✅ | Built-in agents such as Explore, Plan and general-purpose can be renamed in the roster. |

## 3. Token and cost tracking

| Feature | Status | Summary |
|---|---|---|
| Tokens per message | ✅ | Fresh input, cache write, cache read and output; transcripts are read incrementally. |
| Estimated cost | ✅ | At list prices (`PRICES`, `core.py`). Cache writes are priced by TTL: 5 minutes for subagents, 1 hour for lead sessions. |
| Total per task | ✅ | Matched by board or episode name. Subagents are exact; the PM's share is estimated from which task its turns belong to. |
| Context size | ✅ | Each agent's current per-turn context. |
| Team and all-sessions totals | ✅ | In the top bar, for the selected time window. |
| Cost over time | ❌ | No daily or weekly trend, no average by task type, no before/after comparison; everything is computed on the fly from the window. |
| Budget alert | ❌ | No alert when a task or agent goes over a set amount. |

## 5. Token-saving measures

| Feature | Status | Summary |
|---|---|---|
| Tool whitelists | ✅ | A `tools:` line in every agent; starting context of about 5–8k instead of 31k. |
| `teammap` code map | ✅ | `endpoint`, `symbol`, `model`, `file`, `search`: answers "where is it, who uses it" in one call. Python via `ast`, TypeScript via the repo's own compiler. |
| `teammap arch [repo]` | ✅ | The repo's stack, how it runs, the infrastructure it uses and the services it calls, in one call. |
| Research tools | ✅ | `teammap impact` (impact of an endpoint, function or model change), `teammap failures` (error groups from saved test output), `teammap relevant` (files, symbols, brief sections and episodes related to a task). Method-aware `api_route` indexing, project `internal/` traceback frames, validated repository names and numeric CLI options. Exact/inferred distinction, coverage gaps, records tied to an input fingerprint (`<team>/graph/research/`). Details and measurements: [RESEARCH-TOOLS.md](RESEARCH-TOOLS.md). |
| teammap nudge | ✅ | A `PreToolUse` hook in the engineer, QA and integration-checker files suggests the `teammap` command for a grep after a symbol or route, or a whole read of a long source file. Never blocks; once per suggestion per session; `aiset-init --no-nudge` turns it off. |
| `teammap code <name>` | ✅ | Exact and same-file matches show source with line numbers; ambiguous cross-file matches list candidates and can be narrowed by repo or path (exit 3), substring guesses are labeled, and misses exit 4. |
| Reading rules | ✅ | Based on measurements: pieces needed together in a single Bash call, the part to edit via Read with `offset`/`limit`, never a whole long file. `LIMIT` on DB queries, a narrow target first for tests. |
| Assignment size | ✅ | Work that fits in 40–60 tool calls; anything bigger is split into sequential parts. |

| Feature | Status | Summary |
|---|---|---|
| Alternate transcript root | ✅ | `AISET_CLAUDE_HOME` moves the transcript data root and, without a workspace, the fallback team and agents folders. |
| No dependencies | ✅ | Only the Python 3 standard library; the repo's own `typescript` package for parsing TypeScript. |

| Automated tests | 🟡 | `tests/`: task ids, import resolution and the research tools (parsers checked against real pytest/unittest/Node output; end to end on a small workspace). Transcript parsing (`core.py`) still has no tests. |

## Gaps and proposals

In priority order. "Why it matters" describes what is gained once it's solved.

| # | Gap | Why it matters | Proposal |
|---|---|---|---|
| 1 | ~~**Board name format in the template didn't match (bug)**~~ ✅ 2026-10-17 | The template now uses `<yyyy-mm-dd>-<slug>`; `core.py` also recognises old `<yyyymmdd>-<slug>` boards and maps them to the same task key (`task_id`), so old boards match their episodes. | Existing teams' agent files should be regenerated with `init_team.py`. |
| 3 | **The rules' effect hasn't been measured** | The model-choice, reading and cache rules are based on data, but what happened afterwards wasn't measured. | A "period comparison" in the office: $ per task, Sonnet/Opus ratio, context per call, cache writes caused by late resumes; before/after. |
| 4 | **No cost history** | Everything is computed on the fly from the time window; trends and averages can't be seen. | Write closed tasks' tokens and cost to the episode or to a small JSON/SQLite file; add a trend chart to the Tasks tab. |
| 5 | **No budget or anomaly alerts** | A 22M-token task was only noticed afterwards. | A threshold per task or run; when exceeded, a warning on the card and banner, with an optional notification. |
| 6 | **No automated tests** | Parsing and matching are heuristic; if Claude Code's transcript format changes, they break silently. | A small test set for `core.py` (task matching, `bash_targets`, cost) using sample transcripts. |
| 7 | **Permission-request detection is a guess** | "Waiting for approval?" relies on 2 minutes of silence; it can give false alarms or show up late. | Use a Claude Code hook (e.g. the notification hook) to write the state to a file and read it in the office. |
| 8 | **`teammap` ranking** | For definitions with the same name, the v1 file can rank ahead of v2 (e.g. `buildDriverShiftRows`). | Ranking that puts the most recently changed file or the active module first; suggest a `--repo`/path filter. |
| 9 | **Route resolution is limited** | The Bash resolver knows the common patterns; reads via `python -c`, `>file` without a space and dynamic paths slip through. The last 600 steps per agent are shown. | Measure the missed patterns and add them; show the number of "unresolved commands" in the route. |
| 10 | **An old copy is still around** | `~/projects/learnings/agent-office`, outside git, still exists; it once led to changes being made in the wrong place. | Delete it or turn it into a symlink to the repo. |
| 11 | **No light theme** | The UI is dark only. | An optional light theme. |

When one of the items above is picked up, update this table: a finished item moves to its section as ✅.
